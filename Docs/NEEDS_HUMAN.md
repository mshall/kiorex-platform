## Provider go-live (every third-party provider is MOCKED until the dedicated pre-launch pass, in staging first)

Founder decision 19 Nov 2026. Each integration sits behind an adapter with `MODE=mock|real` (default `mock`); mocks exercise the same code paths (template rendering, consent, quiet hours, delivery states, signed callbacks). No real credentials exist in code. Switching a provider to real = implement the adapter class named below, supply the keys via secrets (never `.env` in git), run the staging checklist, then flip the mode.

## Rev 2.3 home visits / Nurse: decisions and gates the build did not invent

- **Gates are human-only** (ADR-024): GHV1 counsel memo, GHV2 CMO safety protocol, GPR1 physiotherapy category, GKN1 nursing sign-off (`nurse.care_plans`, `nurse.mar`), GKN2 counsel memo (`nurse.individual_kiorex_listing`). Record them in the super admin (`PUT /admin/flags/{key}/gate` or `PUT /admin/gates/{gateId}` for a shared gate). The dev seed only adds `DEV-ONLY-NOT-A-REAL-GATE:<GATE>` rows for GHV1/GHV2/GPR1 (never GKN1/GKN2, never in production).
- **Home deposit amount (BR54)**: required by default but the amount is a KX-12 decision: `HOME_DEPOSIT_DEFAULT_MINOR` (falls back to `DEPOSIT_DEFAULT_MINOR`), 0 = unset => no deposit is collected and the booking records `depositPolicy: HOME_DEFAULT_REQUIRED_AMOUNT_UNSET`.
- **Cluster definition for the >=50 home-enabled-provider gate**: the docs do not define "cluster"; the metric uses the provider governorate (`GET /admin/home-visits/gate-metric`). Confirm or give the cluster list.
- **Home surcharge shape**: assumed a Kiorly fee entry may carry `serviceLocation: HOME` and `homeSurcharge` (major units, added to `amount`); shown as "visit fee incl. home surcharge" (KXMHV04). Confirm with the Kiorly home-visit implementation.
- **Unsafe-abort deposit outcome**: ops decide release-to-provider vs refund-to-patient per case (reason required); no default policy is invented.
- **Consent copy** for `VISIT_STATUS_SHARING` and the family contact attestation, the safety-card wording and Arabic profession labels are drafts (AR/EN review).
- **Care plans (P3)** and `ReferralIssued` / `MedicationOrderShared` relay are not product-ready: care plans sit behind GKN1; the two Kiorly-to-Kiorly events are acknowledged and ignored.
- **Nurse -> Lab relay (KNLAB01)**: (a) the `LabOrderPlaced.patient` block (name, date of birth, sex, phone) travels through Kiorex under the consent token and is not stored here: counsel/DPO to confirm this is acceptable for a pass-through processor, or choose a vault-fetch alternative; (b) the consent token is not re-verified at Kiorex (presence only; the clinic mints it, the lab stores its hash); (c) no Kiorex capability flag switches the relay OFF (the clinic's `clinic.lab_order_handoff` does): add a catalogue key if super admin needs a global kill switch; (d) production needs a `lab_nurse` registration (a KIORLY_NURSE integration client created by the lab owner), made by ops.
